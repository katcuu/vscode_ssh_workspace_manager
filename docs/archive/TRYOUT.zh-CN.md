# 0.0.3 体验测试

先在一台已能通过官方 Remote SSH 连接的 Linux 服务器上试用。优先使用普通开发目录，第一轮选择“新窗口打开”。本扩展不改写 SSH 配置，不删除远程文件。

## 安装

扩展面板右上角 `…` → 从 VSIX 安装，选择 `artifacts/ssh-workspace-manager-0.0.3.vsix`。已安装旧版时用相同步骤更新，按 VS Code 提示重新加载窗口。

左侧活动栏应显示 **SSH Manager** 的服务器＋文件夹图标。点击图标，再点侧栏 **打开管理页面**。侧栏标题右上角也有打开按钮。活动栏图标曾被隐藏时，可右击活动栏重新勾选 **SSH Manager**；备用入口是命令面板 `SSH Manager: 打开管理页 / Open Dashboard`。

## 请验证的流程

1. 管理页能列出 SSH 配置中的服务器；完整路径易于辨认。
2. 选服务器，点击“连接并浏览”。已有密钥 / agent 能直接登录时，不应提示密码；无可用密钥且服务器允许密码时，应显示密码框。
3. 浏览至少两层目录。单击只选中，双击进入，上一级和路径栏可用；包括一个长路径或带空格 / 中文的目录。
4. 点击“新窗口打开”，确认目标服务器和目录正确；新窗口再次打开管理页，检查最近记录。
5. 收藏一个目录，在其他 VS Code 窗口查看；重命名、搜索并重新打开。
6. 取消一次密码输入，再重试；若方便，关闭后台连接后重连。
7. 分别删除一条收藏和一条历史记录，确认它们从管理页消失，其他窗口也同步移除。取消收藏只移除星标，仍保留历史记录。删除记录保留服务器上的文件夹；再次实际打开后会重新记录。

首次未知主机指纹需要与可信来源核对。已有 known_hosts 中相同算法的指纹发生变化时会停止连接。后台浏览成功不代表正式编辑连接已建立。

## 反馈格式

提供本机系统、VS Code 版本、认证方式（密钥 / agent / 密码）、失败步骤和页面错误文字即可。可匿名化服务器别名与路径；不要提供密码、私钥或完整敏感配置。

## 仍待验证

macOS / Windows 真实 OpenSSH、远程 Linux SFTP、Remote SSH 窗口打开、实际多窗口记录同步。ProxyJump / ProxyCommand 等复杂连接由后续版本补齐；原型遇到这些配置会停止后台连接。

卸载：在扩展面板移除本扩展即可。项目记录是本机元数据；服务器上的目录与源码不受影响。
